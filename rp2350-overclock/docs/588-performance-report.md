# RP2350 @ 588 MHz 全量性能报告

日期：2026-10-18
平台：MuLuoxing RP2350A（QFN-60，30 GPIO，16 MB flash），SDK 2.3.1
工作点：**clk_sys = 588 MHz，DVDD = 1.70 V**（VREG 直供，钳位已解锁）
对照：150 MHz / 1.10 V（原厂标称）

数据来源：本仓库 `bench/`、`coremark/`、`mc/`、`mixed/`、`render/`、`srambench/`、`piobench/`、`dmabench/`、`hstxbench/`，日志见 `logs/`。

## 6. DMA

| 项目 | 结果 |
|---|---|
| SRAM→SRAM 拷贝上限 | **3.99 B/clk（2.35 GB/s @588）** |
| 双缓冲（1024/4096/16384 字分块） | **无收益**（−3.5% / −0.8% / −0.2%） |
| DMA 满载时 CPU 读带宽 | 1.60 → **1.20 B/clk（−25%）** |

双缓冲只在"生产者比总线慢"时有价值；PIO TX 小分块（256 字）阻塞重装损失 19%，即其收益上限。

## 7. HSTX

- 消费规则：**1 个 32 位字（3×10 bit TMDS 符号 = 1 像素）每 5 个 HSTX 时钟**；实测 48 MHz 档 9.60 Mword/s，与 clk/5 逐位吻合。
- **规格上限 150 MHz**（数据手册 p.1196：“The maximum frequency for the HSTX clock is 150 MHz”）→ 规格内像素率封顶 **30 Mpix/s**。
- 实测在 clk_hstx = 588 MHz 下仍跟频工作，消费 ≥**97.24 Mword/s**（CPU 供数上限，3.92× 线性）；117.6 Mpix/s 为 clk/5 外推，未直接测到。
- 每 lane 引脚速率 1.176 Gbit/s，信号完整性无保证——**能算不等于能出画面**。
- **CPU 喂不满**：150 MHz 下只有 24.81 Mword/s（天花板的 83%）→ 必须 DMA。
- 已知坑：`clock_configure(clk_hstx, …)` 的分频不生效，需直接写 `CLOCKS_CLK_HSTX_CTRL_DIV`。

分辨率上限：720p60 ✅、1080p30 ✅、1080p60 ❌。

## 9. 结论

1. **588 MHz 是真实的 3.92×**，计算、PIO、DMA 全部线性，无静默算错（约 2400 轮负载、0 校验错误）；**600 MHz 在单点复测下同样稳定**（4.00×，12 路满载需 1.80 V）。
2. **代价是 9.36× 功耗、能效降到 0.42×**；600 MHz 不是热墙——早前「~52 °C 复位」是多步 sweep 连续换挡的入口温度所致，单点复测稳定（见 §1 勘误）。
3. **588 下可用组合极窄**：M33×2 只能跑 flash；SRAM 执行、H3 双核、混合架构全挂。
4. **XIP 是唯一不随频率走的指标（18 MB/s，1.13×）**——高频下所有热代码必须在 SRAM。
5. **真正的瓶颈已经不在 CPU**：SRAM 2.35 GB/s、PIO 2.22 GB/s、HSTX 117.6 Mpix/s，都能喂饱 588 的算力；瓶颈是"CPU 自己吃不动的 0.94 GB/s 访存"和"XIP"。
6. **产品工作点建议**：常态 336 MHz / 1.15 V（2.24×，能效 0.91×），转场/加载临时 504 MHz / 1.50 V；588 只作基准与短时性能模式。
