# SRAM 带宽实测（RP2350）

日期：2026-10-18
固件：`srambench/`（纯读 / 纯写 / 拷贝 / 8 位访问 / DMA 拷贝 / 双核读）
条件：两块 128 KB 缓冲区（`0x20001400` / `0x20021400`），热函数全部 `__not_in_flash_func`，`-O2`

## H3（Hazard3 / RISC-V）同场对比

同一份源码用 `rp2350-riscv` 构建（`build_rv150` / `build_rv588`，GCC 14.2），其余条件完全相同：

| 测试 | M33 @588 | **H3 @588** | 差异 |
|---|---|---|---|
| 纯读 32 位 | 1.60 B/clk | **1.68 B/clk** | H3 **+5%** |
| 纯写 32 位 | 2.46 B/clk | **3.20 B/clk** | H3 **+30%** |
| 拷贝 32 位 | 1.52 B/clk | **1.60 B/clk** | H3 +5% |
| 纯读 8 位 | 0.42 B/clk | **0.44 B/clk** | 持平 |
| 拷贝 8 位 | 1.73 B/clk | **1.45 B/clk** | H3 **−16%** |
| DMA 拷贝 32 位 | 4.00 B/clk | **4.00 B/clk** | 相同（与核无关） |
| 双核同时纯读 | 3.04 B/clk | **2.94 B/clk** | M33 +3% |

绝对值（H3）：读 0.99 GB/s、写 1.88 GB/s、拷贝 0.94 GB/s、DMA 拷贝 2.35 GB/s。

结论：

- **32 位流式访存 H3 略强于 M33**（写高 30%），不是"H3 啥也不行"。
- **字节级拷贝 H3 弱 16%**，是 RV32 缺少位段/半字处理指令的代码生成代价。
- **双核访存 M33 组合略优**（3.04 vs 2.94 B/clk）。
- 所有 B/clk 在 150/588 两个频点上保持稳定（H3 的写从 2.91 升到 3.20，属存储缓冲在高频下的相对收益）。



## 结论

1. **SRAM 本身的极限是 1 读 + 1 写 / 时钟 = 4 B/clk**：588 MHz 下即 **2.35 GB/s**，由 DMA 拷贝实测钉死。
2. **M33 核心吃不满 SRAM**：纯读只有 1.60 B/clk（0.4 word/clk），写 2.46 B/clk（0.6 word/clk），拷贝 1.52 B/clk。两个核加起来 3.04 B/clk，仍低于 DMA 的 4.00。
   → 瓶颈是**核的访存流水线**（无缓存、单 AHB 端口、加载延迟 2 周期），不是 SRAM。
3. **B/clk 在 150 与 588 完全一致**，说明 588 MHz 下访存时序没有任何效率损失，纯按频率线性放大。
4. 早先 `bench` 记录的 "SRAM 587 MB/s @588" 是**字节宽循环**的口径（≈1 B/clk），不是 SRAM 带宽；本次 `copy8` 在 588 下是 1.02 GB/s，`DMA copy32` 是 2.35 GB/s。
5. 与 PIO 侧的交叉验证：PIO TX 从 SRAM 取数在 588 下达到 1.83 GB/s（0.78 word/clk），介于 CPU 的 0.4 与 DMA 的 1.0 word/clk 之间 —— 因为 TX 侧还有 autopull 停顿。三者互相自洽。

## 对渲染引擎的含义

- 逐像素循环每读一个字只有约 0.4 word/clk 的能力 → **像素运算应尽量在寄存器里做**，避免每像素回读内存。
- 帧缓冲搬运用 DMA/PIO，不要用 CPU 拷贝循环（DMA 快 2.6 倍）。
- 双核并不会让访存带宽翻倍（3.04/4.00 = 76%），加核主要提升的是**计算**并行度，不是访存。

## LDM/STM 反证（150 MHz 实测）

如果瓶颈是"指令条数"，`ldmia`（一条指令搬 4 个字）应该显著提升；实测相反：

| 测试 | 标量 | LDM/STM | 差 |
|---|---|---|---|
| 纯读 32 位 | 1.60 B/clk | **1.33** | −17% |
| 拷贝 32 位 | 1.45 B/clk | **1.33** | −8% |

结论：**瓶颈不是指令流，是单核访问 AHB 的服务速率**（每拍最多 1 个 32 位事务，且存在固定延迟）。多字指令只是把同样的请求打包，拿不到额外带宽。

推论：**每载入 1 个字，只付得起约 2.5 条指令**（1 / 0.4 word/clk）。低于这个算术强度的内核（拷贝、校验、滤镜、调色板展开）是访存瓶颈；高于它的（光栅化 11 时钟/像素、约 1–2 次访存）仍是指令瓶颈。
