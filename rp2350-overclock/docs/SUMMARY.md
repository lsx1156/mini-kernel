# RP2350 性能实测汇总

**对象**：MuLuoxing RP2350A 开发板（QFN-60，30 GPIO，16 MB flash，CHIP_ID `0x30004927`，UID `8CEDF8FC0AD7BB65`）
**环境**：Pico SDK 2.3.1；ARM GCC 13.4（MSYS2）/ 10.3.1；RISC-V GCC 14.2
**日期**：2026-10-18
**口径**：标注「实测」的为板上跑出的数字；标注「外推」的按已验证的线性关系推算，未直接测量。

---

## 0. 一页结论

| 维度 | 结论 |
|---|---|
| 频率 | 150 → **588 MHz**（3.92×）@1.70 V，30 s 拷机 184 轮 0 错；600 MHz 热限制不可用 |
| 代价 | 动态功耗 **9.36×**，能效降到 **0.42×**；1.70 V = 标称 +490 mV |
| 算力 | CoreMark M33 **1684.687**、H3 **1705.451**；CM/MHz 在 150/396/588 恒定 → 超频无架构损耗 |
| 架构 | M33 强在浮点/DSP（浮点 15×、光照 24×）；H3 强在整数与 32 位流式访存（写 +30%） |
| 内存 | SRAM 端口 **4 B/clk = 2.35 GB/s**；CPU 只吃 1.6 B/clk，必须靠 DMA |
| PIO | TX 总线饱和 **555 Mword/s（2.22 GB/s）**，4 SM 即满；RX **7.03 Gsample/s**（12 SM 线性） |
| DMA | **4.00 B/clk**，严格跟频；双缓冲对内存拷贝无收益 |
| HSTX | 规格 150 MHz 封顶（30 Mpix/s）；实测 588 下跟频（≥97.24 Mword/s），但引脚 1.176 Gbit/s 电气无保证 |
| XIP | **18 MB/s @588（仅 1.13×）**——唯一不随频率走的指标，热代码必须进 SRAM |
| 定位 | 适合 320×240 / 480×272 2D 掌机；不适合 640×480 galgame 掌机 |

| 内核 | M33 @150 | H3 @150 | M33 @588（外推） |
|---|---|---|---|

### 3.2 150 MHz 缩放基线

| 配置 | 每核保留率 | 合计 |
|---|---|---|
| M33 ×2 flash | 98.7% | 1.974× |
| H3 ×2 flash | **79.8%** | 1.595× |

H3 双核 flash 掉 20% 的原因是**共享 16 KB XIP 缓存**，不是 SRAM 带宽。

## 4. 内存系统（588 MHz）

| 测试 | M33 | H3 |
|---|---|---|
| 纯读 32 位 | 1.60 B/clk（0.94 GB/s） | **1.68（0.99）** |
| 纯写 32 位 | 2.46（1.45） | **3.20（1.88）** |
| 拷贝 32 位 | 1.52（0.90） | **1.60（0.94）** |
| 纯读 8 位 | 0.42 | 0.44 |
| 拷贝 8 位 | **1.73** | 1.45（0.85） |
| **DMA 拷贝** | **4.00（2.35 GB/s）** | 4.00（2.35） |
| 双核同时读 | **3.04** | 2.94 |

- B/clk 在 150 与 588 完全一致 → 高频无访存退化。
- **SRAM 端口极限 = 1 读 + 1 写/时钟 = 4 B/clk**，由 DMA 拷贝钉死；CPU 只有 40%，双核也只有 76%。
- 结论：**逐像素循环必须把数据留在寄存器**；帧缓冲搬运一律走 DMA/PIO。

## 5. PIO（通讯与搬运的真实能力）

### 5.1 TX（`out pins, 32` + autopull + DMA）

| 配置 | 150 MHz | 588 MHz |
|---|---|---|
| 1 SM（重复源） | 116.57 Mword/s（1.287 clk/word） | **456.90** |
| 1 SM（SRAM 源） | 116.40 | 456.35 |
| 4 SM | 141.64（饱和） | **555.17（饱和）** |
| 8 SM | 141.64 | 555.24 |
| 12 SM | 141.64 | **555.27 Mword/s** |

588 下 = **2.22 GB/s = 17.8 Gbit/s**，0.944 word/clk，**4 个 SM 就吃满总线**。

### 5.2 RX（`in pins, 1`）

| 配置 | 150 MHz | 588 MHz |
|---|---|---|
| 1 SM | 149.99 Msample/s（1.000 clk/sample） | **587.93** |
| 4 SM | 599.73 | 2350.90 |
| 12 SM | 1792.82 | **7028.58 Msample/s** |

12 SM 线性叠加到 **7.03 Gsample/s**（= 12 通道 × 588 MS/s），无饱和。

### 5.3 用法

- 显示/并口输出：**1 个 SM 足够**，加 SM 无效（总线墙）。
- 多通道采样：堆 SM 真线性。
- 小分块 + 阻塞重装损失 **19%**（256 字：94.53 vs 116.57 Mword/s）——这是双缓冲在 PIO 方向的收益上限。

## 6. DMA

| 项目 | 结果 |
|---|---|
| SRAM→SRAM 吞吐 | **3.99 B/clk（150 MHz 0.60 GB/s；588 2.35 GB/s）** |
| 双缓冲 vs 阻塞（1024/4096/16384 字） | **无收益**（−3.5% / −0.8% / −0.2%） |
| DMA 满载时 CPU 读带宽 | 1.60 → **1.20 B/clk（−25%）** |

**双缓冲只在「生产者比总线慢」时有价值**（PIO、ADC、SD、I2S）；内存搬运已被端口限死，腾不出空隙。

---

## 7. HSTX

- 消费规则：**1 个 32 位字（3×10 bit TMDS 符号 = 1 像素）每 5 个 HSTX 时钟**。
- 实测验证：clk_hstx = 48 MHz → **9.60 Mword/s**（理论 9.60，误差 <0.1%）。
- 规格上限：数据手册 p.1196「**HSTX 时钟最高 150 MHz**」→ 规格内 **30 Mpix/s**。
- 超规格实测：clk_hstx = 588 MHz 下 CPU 可推 **97.24 Mword/s** 且 FIFO 从未填满 → **HSTX 确实跟频，消费 ≥97.24 Mword/s**；117.6 Mpix/s 为 clk/5 外推，未直接测到。
- **CPU 喂不满**（150 MHz 下 24.81 Mword/s，仅天花板的 83%）→ 必须 DMA。
- 引脚速率 = 2 × clk_hstx（588 下 1.176 Gbit/s/lane）→ **电气上无保证**。
- 已知坑：`clock_configure(clk_hstx, …)` 的分频不生效，需直接写 `CLOCKS_CLK_HSTX_CTRL_DIV`。

## 8. 显示与帧预算

| 负载 | 336 MHz | 588 MHz | 占 16.67 ms |
|---|---|---|---|
| 480×272，3 层合成 | 12.86 ms | **7.35 ms**（折算） | 44% |
| 480×272，脏矩形典型 | ~3.4 ms | ~2 ms | 12% |
| 640×480，1 层 | 10.08 | 5.76 | 35% |
| 640×480，3 层 | 30.25 | **17.29** | **103.7%** ❌ |

- 480×272 = PSP 原生分辨率，单缓冲 255 KB + 脏矩形 + 每 16 行扫描线跟随合成（双缓冲 510 KB 装不下）。
- 640×480 帧缓冲 600 KB > 520 KB SRAM，即使 588 三层也超帧预算。
- 显示输出需求：480×272@60 = 15.7 MB/s；PIO 单 SM 400 MB/s、HSTX 30 Mpix/s，均远超。
- **VGA 更糊**：LCD 内部 scaler 重采样、无帧缓冲、需电阻 DAC、做不成掌机 → 走并口 TTL 或 HSTX→DVI。

## 9. 掌机选型与内核分配

**适用范围**：RP2350 适合 320×240 / 480×272 的 2D、galgame 掌机；不适合 640×480 的 galgame 掌机（后者选 ESP32-P4：JPEG 硬解 + PPA + MIPI-DSI + 32 MB PSRAM）。

| 内核 | 职责 | 依据 |
|---|---|---|
| M33 core0 | 渲染 / 物理 / 浮点 | FPU + DCP + DSP；浮点 15×、光照 24× 领先 H3 |
| M33 core1 | 第二渲染 / 音频 / 流控 | 588 下 M33×2 flash 可跑 |
| H3 | 整数协处理 / 控制面 | CoreMark/MHz 2.900 更高；32 位流式写快 30%；混合架构 100% 保留 |

**四条硬规则**：热代码进 SRAM（XIP 只有 18 MB/s）；两核不同时从 flash 取指；搬运优先 DMA/PIO；每核用 `time_us_64()` 打点闭环。

**工作点建议**：常态 **336 MHz / 1.15 V**（2.24×，能效 0.91×），转场临时 504/1.50；**588 只作短时性能模式与基准**。

## 10. 方法论与工程坑

### 10.1 测量方法

- 超频：先加 `QMI.M0_TIMING.CLKDIV` 再抬 `clk_sys`，切换代码放 RAM（`__no_inline_not_in_flash_func`）+ 关中断；SDK 的 `set_sys_clock_khz()` 不处理 QSPI 分频。
- 跨复位频率地图：看门狗 + scratch 寄存器；**UF2 刷写不清 scratch**，必须 `FRESH=1` 强制清零。
- CoreMark 必须 ≥10 s（迭代数随频率放大：588→20000、396→14000），否则判分无效。
- 微基准要避免测量伪影：读循环用 4 个独立累加器（单累加器会被依赖链限制到 1.28 B/clk，修正后 1.60）。
- 高吞吐下**不要用中断计数做完成判据**（1023 个实际完成只数到 903）。
- 双缓冲/链式 DMA **绝不能在 ISR 里自我触发**：会形成中断风暴打死 CPU、USB 断流。

### 10.2 编译与工具链

- `binutils 2.47` 拒绝任何 linker script `INCLUDE` → 用 `tools/flatten_ld.py` 展平。
- RISC-V GCC 14.2 默认选到带 F/D 的 multilib（`zcmp is incompatible with 'd'`）→ 显式加两处 `-L …/rv32imac/ilp32`。
- RISC-V 构建：`-DPICO_PLATFORM=rp2350-riscv`；混合架构必须 `multicore_launch_core1_raw(entry, sp, mtvec)`。
- 16 MB flash 需 `-DPICO_FLASH_SIZE_BYTES=16777216`（pico2 板定义默认 4 MB）。
- UF2 family id：ARM-S `0xe48bff59`、RISC-V `0xe48bff5a`、ARM-NS `0xe48bff5b`。

### 10.3 串口（最费时间的坑）

- 现象：COM 口打开阻塞、读报 `ClearCommError`、日志 0 字节。
- **根因不是 Windows 驱动，是固件**：中断风暴把 CPU 占满，USB 后台任务得不到调度。
- 对策：ISR 里不做自我触发；加硬件看门狗（`watchdog_enable(12000)`）让挂死自愈；抓取脚本用带超时的守护式打开。
- 归档固件务必刷回 **150 MHz / 1.10 V** 安全镜像。
