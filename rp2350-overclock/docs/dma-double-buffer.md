# DMA 双缓冲实测（RP2350）

日期：2026-10-18
固件：`dmabench/`（SRAM→SRAM 32 位拷贝，单通道阻塞 vs 双通道 ping-pong）
条件：150 MHz / 1.10 V，每档 512K words（2 MB）

## 阻塞 vs 双缓冲

| 分块（words） | 阻塞 | 双缓冲 | 增益 | B/clk |
|---|---|---|---|---|
| 1024 | 0.58 GB/s | 0.56 GB/s | **−3.5%** | 3.89 → 3.75 |
| 4096 | 0.60 | 0.59 | −0.8% | 3.97 → 3.94 |
| 16384 | 0.60 | 0.60 | −0.2% | 3.99 → 3.98 |

单通道连续拷贝上限：**0.60 GB/s = 3.98 B/clk**（SRAM 理论上限 4 B/clk）。

## 结论

1. **SRAM→SRAM 这条路上双缓冲没有收益**：阻塞式在 1024 字分块就已经跑到上限的 97%，双缓冲把剩余 3% 也拿不回来，反而因为进中断、软件启动另一通道多花 3.5%。
2. **原因是搬运速度被 SRAM 端口限制**（4 B/clk），CPU 重装通道（约几十纳秒）比一个分块的传输时间短得多，空隙本来就看不见。
3. **双缓冲只在"生产者比总线慢"时才有价值**：PIO（1 字/时钟）、ADC、SD 卡、I2S 这类源，此时 CPU 重装会造成真实丢数据或降速。

## 量化的适用边界（PIO TX 侧，150 MHz）

同一套 TX 通路在分块 256 字、阻塞重装时只有 **94.53 Mword/s**，而单次大传输是 **116.57 Mword/s**——**19% 的损失**。这 19% 就是双缓冲在 PIO/外设方向上的收益上限。分块越大损失越小。

## CPU 与 DMA 抢内存

| 场景 | CPU 读带宽 |
|---|---|
| CPU 单独流式读 | 1.60 B/clk（0.24 GB/s） |
| DMA 拷贝同时进行 | **1.20 B/clk（0.18 GB/s）** |

**DMA 满载时 CPU 读带宽降 25%**。含义：显示扫描 DMA 常开时，渲染核的访存能力要按 0.75 倍折算；这也是把热数据留在寄存器而非反复读内存的另一个理由。
